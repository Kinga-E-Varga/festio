## Possible bugs

This part is report-only: nothing in the code was changed.

### The guest page ignores Protected, Hidden, closed and past
**Problem:** Anyone with the link sees the whole invitation. A Protected invitation (for example `/maria-andrei`, password `andrei26`) opens with no password box at all. The page also never checks if the invitation is Hidden, if the reply form has closed (24h rule or the host's own closing time), if the event is past or cancelled, or if its data was already deleted. In all those cases guests still get the full card and an open reply form.
**Where:** `src/app/invite/[invite]/page.tsx:23-43`. The only check it makes is `repliesPaused`.
**How sure:** Confirmed (traced it). Right now only `/maria-andrei` has a template, and it is the Protected one.
**Suggested fix:** Before drawing the card, decide what the guest may see. Hidden or deleted shows a "not available" page. Protected shows a password box first. Cancelled shows the header plus the host's message. When the reply window is closed or the event is past, the panel shows a "replies are closed" line, like the paused one does now.

### The event editor saves even when a field shows an error
**Problem:** The Save button looks only at "something changed" and "warnings read". It ignores every error on the page. A host can save with a link that is taken, reserved or too short/long, a Protected password that breaks the rules, expected guests of 0 or fewer than the replies so far, or a closing time after the cut-off. The toast says "Changes saved". On top of that, an empty link (or one made only of spaces) shows no error at all. Protected with an empty password also shows no error, because the password is checked only once something is typed.
**Where:** `src/components/dashboard/event-editor/useEventForm.ts:197` and `:271` (`canSave`). Empty link: `:177`. Empty password: `:191-194`.
**How sure:** Confirmed (traced it).
**Suggested fix:** Let Save through only when there is no slug error, no password error, no expected-guests error and no "close too late". Treat an empty link as "too short". When visibility is Protected, require a password.

### The guest's Send button does nothing when no answer is picked
**Problem:** A guest types their name, presses Send and forgets "Going / Not going". Nothing happens and no message says why. The form looks broken.
**Where:** `src/components/invitation/RsvpForm.tsx:48-55` checks only the names. `RsvpPanel.tsx:74-76` then stops without a word, because `buildPayload` returns null (`useRsvpForm.ts:52`).
**How sure:** Confirmed (traced it).
**Suggested fix:** On submit, also check that a choice is picked, and show a short warning next to the two buttons, the same way the empty-name warning works.

### Cancel event and Delete draft act on a single click
**Problem:** The spec asks for a detailed confirmation and the host's password before an event is cancelled. Here one click on "Cancel event" (or "Delete draft") shows the "done" toast straight away. There is no confirmation and no password step, so a stray click would, once saving is real, cancel a live event.
**Where:** `src/components/dashboard/event-editor/DangerZone.tsx:53` and `:74`.
**How sure:** Confirmed (traced it).
**Suggested fix:** Open a confirmation step first. It should say what happens and how many guests replied, then ask for the password to cancel, or for a plain confirm to delete a draft. Show the toast only after that.

### The invitation editor ignores the 24h lock and the save warning
**Problem:** The text editor at `/invitations/<id>` stays fully editable and "Save" always says saved, even after editing has closed for the event. It also never shows the spec's blocking warning (guests won't be notified, with the reply count) when the invitation is not Hidden. Today every event with a template is still open, so nobody hits it yet.
**Where:** `src/app/[locale]/invitations/[id]/page.tsx:46-51` passes no `locked` or visibility. `src/components/invitation/HostInvitationEditor.tsx:58-60` saves with no checks.
**How sure:** Confirmed in the code. It shows up once a locked event has a template.
**Suggested fix:** Pass the event's `locked` state, visibility and reply count into the editor. When locked, show it read-only. When not Hidden, ask for the "guests won't be notified" confirmation before saving.

### Deletion date and cut-offs shift around daylight-saving changes
**Problem:** The dates are worked out by adding or taking away whole 24-hour blocks. When a clock change falls in between, the result lands an hour off. For Maria & Andrei (6 September 2026), the "data deleted" date shows **4 November** instead of 5 November. Botez Sofia shows 9 December instead of 10. An event on 26 October shows its cut-off as "25 October, 01:00", and one on 30 March shows "28 March, 23:00", which is the wrong day. A server running on UTC would work out a different answer than the host's browser, so a client-rendered card can also get a hydration mismatch.
**Where:** `src/lib/event.ts:121-130` (`contentFreeze`, `deletionDate`). Shown in `DatesThatMatter.tsx:73-74`, `EventRow.tsx:89`, `useEventForm.ts:134-135` and `NotificationsRail.tsx:84`.
**How sure:** Confirmed (ran the same maths with the Europe/Bucharest time zone).
**Suggested fix:** Move by calendar days, not by milliseconds. Build the date from year, month and day and change the day number (`setDate(getDate() ± n)`), so midnight stays midnight.

### The "guests won't be notified" warning only appears after the first reply
**Problem:** The spec says any save while the invitation is not Hidden needs that warning. In the event editor, the link, password and language warnings appear only when `replied > 0`. A Public or Protected event with no replies yet can change its link or password without any warning, even if the link is already out with guests who haven't replied.
**Where:** `src/components/dashboard/event-editor/useEventForm.ts:142` (`shared = event.rsvp.replied > 0`).
**How sure:** Possible. It depends on whether "reply count > 0" was meant as the stand-in for "not Hidden".
**Suggested fix:** Base `shared` on visibility (not Hidden), and keep showing the reply count in the text.

### noindex is a meta tag, not a header
**Problem:** The spec asks for `noindex` headers. The guest page sets only the `robots` meta tag, and only on the page itself. Responses without that tag, such as the 404 for an unknown link, carry nothing. That is weaker than an `X-Robots-Tag` header.
**Where:** `src/app/invite/[invite]/page.tsx:14-16`. `next.config.ts` has no `headers()`.
**How sure:** Possible. It depends on how strictly "headers" was meant.
**Suggested fix:** Add an `X-Robots-Tag: noindex, nofollow` header for guest-link paths in `next.config.ts`, and keep the meta tag too.
